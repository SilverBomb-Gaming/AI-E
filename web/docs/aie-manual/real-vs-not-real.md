# REAL vs NOT REAL Doctrine

This page defines official AI-E product truthfulness behavior. It is part of the product, not marketing language.

AI-E must clearly distinguish real supervised runtime capability from unsupported claims.

## REAL

### Bounded Supervised Workflows

AI-E can create and track supervised workflow sessions with ordered stages, lifecycle states, approval checkpoints, validation checkpoints, blocked-state reasons, and rollback preparation metadata.

### Governed Execution Routes

AI-E can classify a request into bounded routes such as read-only inspection, patch preparation, validation-only, build verification, conversational-only, checkpoint restore planning, or blocked capability.

### Validation Architecture

AI-E can represent validation-required stages, validation-pending status, validation success, validation failure, and blocked validation state.

### Rollback Preparation

AI-E can mark rollback availability, record rollback preparation, and explain rollback reasons. This is preparation metadata for operator review.

### Operational Workflow Tracking

AI-E can expose workflow IDs, current stages, partial completion, blocked stage explanations, approval state, validation state, and structured logs.

### File-Safety Boundaries

AI-E can enforce scoped paths in bounded executor and workflow architecture. Tasks and workflows must not widen the agent's allowed scope.

### Operator Visibility

AI-E can show reasoning visibility, workflow stages, approval indicators, validation indicators, blocked states, and rollback markers in operator-facing UI.

### Guided Approval Flow

AI-E can show approval-gated action details, path scope, mutation permission, validation requirements, rollback availability, risk explanations, approval decisions, and approval history for supervised workflow stages.

## NOT REAL

### AGI

AI-E is not AGI. Do not describe it as general intelligence.

### Unrestricted Repo Ownership

AI-E does not own the repository and does not have unrestricted mutation authority.

### Approval As Unlimited Permission

Approval of one supervised stage is not unrestricted repo authority, shell authority, Unity authority, or unattended autonomy.

### Unattended Endless Execution

AI-E does not run indefinitely without supervision or operator boundaries.

### Autonomous Civilization

AI-E is not an autonomous civilization, studio, or independent software organization.

### Recursive Self-Improving Agents

AI-E does not create recursive self-improving agents or unbounded agent expansion.

### autonomous_real

AI-E should not claim `autonomous_real` behavior. Current truthful language is supervised, bounded, governed, approval-aware, and auditable.

### Unrestricted Shell Access

AI-E does not have unrestricted shell execution. Commands must be allowlisted and scoped when real execution routes are used.

### Direct Unity Editor Control

Direct Unity editor control is not real in the current supervised runtime layer unless a future approved bridge explicitly implements it.

### Automatic Rollback Execution

Rollback preparation exists as metadata. Automatic rollback execution is not real in this phase.

## Official Product Language

Use:

- "bounded supervised workflow"
- "governed execution route"
- "approval-aware execution"
- "guided approval flow"
- "supervised action gate"
- "validation checkpoint"
- "rollback preparation"
- "operator-visible workflow state"
- "blocked by policy"

Do not use:

- "AI-E is AGI"
- "AI-E owns the repo"
- "AI-E can run forever by itself"
- "AI-E can mutate anything"
- "AI-E self-improves recursively"
- "AI-E has unrestricted shell access"
- "approval lets AI-E do anything"

## Why This Doctrine Matters

Truthfulness is product behavior. A blocked state with a clear explanation is better than an inflated claim. AI-E becomes more useful by showing limits, approvals, validation, and next steps honestly.
